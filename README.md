# Cash Flow Backend

NestJS backend for the Cash Flow personal finance application.

---

## Budget API

Все эндпоинты требуют JWT-аутентификации (`Authorization: Bearer <token>`).

Base path: `/budget`

---

### Концепции

| Сущность                  | Описание                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `BudgetEntity`            | Лимит расходов по одной категории за период. Для `MONTHLY` хранится поле `month` (первое число месяца, UTC). |
| `MonthlyBudgetPlanEntity` | Финансовый план на месяц: ожидаемый доход (`projectedIncome`), уникален по `(user, month)`.                  |
| `BudgetAdjustmentEntity`  | История изменений лимита — аудит-лог каждой операции extend/freeze-reallocate.                               |
| `BudgetPeriod`            | `MONTHLY` — единственный поддерживаемый период на данный момент.                                             |
| `AdjustmentSource`        | `income_increase` — доход вырос; `budget_reallocation` — перераспределение между бюджетами.                  |

---

### Эндпоинты

#### `GET /budget/category/:categoryId`

Возвращает активный MONTHLY-бюджет категории за текущий месяц вместе с вычисляемыми полями.

**Параметры пути**

| Параметр     | Тип      | Описание                                  |
| ------------ | -------- | ----------------------------------------- |
| `categoryId` | `number` | ID категории (должна быть типа `EXPENSE`) |

**Ответ `200`**

```json
{
  "data": {
    "budgetId": 1,
    "categoryId": 3,
    "period": "MONTHLY",
    "limitAmount": "15000.00",
    "collectedAmount": "8500.00",
    "remaining": "6500.00",
    "isActive": true,
    "isAutoGenerated": false
  }
}
```

| Поле              | Описание                                                                             |
| ----------------- | ------------------------------------------------------------------------------------ |
| `limitAmount`     | Установленный лимит расходов                                                         |
| `collectedAmount` | Сумма транзакций по категории за текущий месяц (вычисляется из `transaction_entity`) |
| `remaining`       | `limitAmount - collectedAmount`                                                      |

**Ошибки:** `400` — категория не `EXPENSE`; `404` — категория или активный бюджет не найдены.

---

#### `GET /budget/plan/current`

Возвращает финансовый план текущего месяца с агрегированными данными.

**Ответ `200`**

```json
{
  "data": {
    "id": 1,
    "month": "2026-07-01",
    "projectedIncome": "80000.00",
    "totalAllocated": "55000.00",
    "available": "25000.00"
  }
}
```

| Поле              | Описание                                                                           |
| ----------------- | ---------------------------------------------------------------------------------- |
| `projectedIncome` | Ожидаемый доход месяца (задаётся через операции extend с `source=income_increase`) |
| `totalAllocated`  | Сумма `limitAmount` всех активных MONTHLY-бюджетов за месяц                        |
| `available`       | `projectedIncome - totalAllocated` (может быть отрицательным)                      |

> Если план на текущий месяц отсутствует, он создаётся автоматически с `projectedIncome = 0.00`.

---

#### `PATCH /budget/:id/freeze`

Замораживает бюджет — устанавливает `isActive = false`. Транзакции по категории продолжают учитываться, но бюджет перестаёт отображаться как активный.

**Параметры пути**

| Параметр | Тип      | Описание   |
| -------- | -------- | ---------- |
| `id`     | `number` | ID бюджета |

**Ответ `200`** — `{ "message": "Budget frozen successfully" }`

**Ошибки:** `404` — бюджет не найден или не принадлежит пользователю.

---

#### `PATCH /budget/:id/unfreeze`

Размораживает бюджет — устанавливает `isActive = true`. Допускается отрицательный `available` (фронтенд должен отобразить предупреждение).

**Параметры пути**

| Параметр | Тип      | Описание   |
| -------- | -------- | ---------- |
| `id`     | `number` | ID бюджета |

**Ответ `200`** — `{ "message": "Budget unfrozen successfully" }`

**Ошибки:** `404` — бюджет не найден.

---

#### `POST /budget/:id/extend`

Увеличивает лимит бюджета. Источник увеличения определяется полем `source`.

**Параметры пути**

| Параметр | Тип      | Описание            |
| -------- | -------- | ------------------- |
| `id`     | `number` | ID целевого бюджета |

**Тело запроса**

```json
{
  "amount": "500.00",
  "source": "income_increase",
  "sourceBudgetId": null,
  "reason": "Бонус"
}
```

| Поле             | Обязательность                               | Описание                                          |
| ---------------- | -------------------------------------------- | ------------------------------------------------- |
| `amount`         | required                                     | Сумма увеличения (десятичная строка, до 2 знаков) |
| `source`         | required                                     | `income_increase` или `budget_reallocation`       |
| `sourceBudgetId` | required если `source = budget_reallocation` | ID бюджета-донора                                 |
| `reason`         | optional                                     | Комментарий                                       |

**Логика по типу `source`**

- **`income_increase`** — `projectedIncome` в `MonthlyBudgetPlanEntity` увеличивается на `amount`; лимит целевого бюджета растёт.
- **`budget_reallocation`** — лимит бюджета-донора (`sourceBudgetId`) уменьшается на `amount`. Валидация: новый лимит донора не может быть меньше уже потраченной суммы.

В обоих случаях создаётся запись `BudgetAdjustmentEntity` (аудит).

**Ответ `200`** — `{ "message": "Budget extended successfully" }`

**Ошибки:** `400` — перераспределение превысит потраченную сумму источника; `404` — бюджет не найден.

---

#### `POST /budget/freeze-reallocate`

Замораживает один бюджет и переносит его **весь лимит** в другой за одну транзакцию.

**Тело запроса**

```json
{
  "fromBudgetId": 1,
  "toBudgetId": 2
}
```

| Поле           | Описание                               |
| -------------- | -------------------------------------- |
| `fromBudgetId` | Бюджет, который будет заморожен        |
| `toBudgetId`   | Бюджет, получающий освобождённый лимит |

**Что происходит:**

1. `fromBudget.isActive` → `false`
2. `toBudget.limitAmount` += `fromBudget.limitAmount`
3. Создаётся `BudgetAdjustmentEntity` с `source = income_increase` и причиной `Freed from frozen budget #<id>`

**Ответ `200`** — `{ "message": "Freeze-reallocate completed successfully" }`

**Ошибки:** `404` — один из бюджетов не найден.

---

#### `POST /budget/generate`

Лениво генерирует MONTHLY-бюджеты на текущий месяц для всех `EXPENSE`-категорий пользователя.

- Идемпотентен: если бюджет по категории за этот месяц уже существует — пропускается.
- Лимит рассчитывается на основе суммы транзакций той же категории за **предыдущий** месяц.
- Если плана на месяц нет — создаётся `MonthlyBudgetPlanEntity` с `projectedIncome = 0.00`.

**Ответ `200`** — `{ "message": "Generation triggered successfully" }`

**Ошибки:** `409` — бюджеты уже существуют (в текущей реализации не выбрасывается, эндпоинт идемпотентен).

---

### Типичный сценарий использования

```
1. POST /budget/generate           — генерация бюджетов на текущий месяц
2. GET  /budget/plan/current       — просмотр плана (projectedIncome, available)
3. GET  /budget/category/:id       — проверка лимита и расходов по категории

// Хочу потратить больше, есть дополнительный доход:
4. POST /budget/:id/extend  { amount, source: "income_increase" }

// Хочу перераспределить лимит с другой категории:
5. POST /budget/:id/extend  { amount, source: "budget_reallocation", sourceBudgetId }

// Категория больше не нужна в этом месяце — освобождаю лимит:
6. POST /budget/freeze-reallocate  { fromBudgetId, toBudgetId }

// Временно остановить учёт бюджета:
7. PATCH /budget/:id/freeze
8. PATCH /budget/:id/unfreeze
```

---

### Модель данных

```
MonthlyBudgetPlanEntity
  id, user_id, month (date), projectedIncome (decimal 12,2)

BudgetEntity
  id, category_id, period (MONTHLY), limitAmount (decimal 12,2),
  month (date|null), startDate (date|null), endDate (date|null),
  isActive (bool), isAutoGenerated (bool)

BudgetAdjustmentEntity
  id, targetBudget_id, sourceBudget_id (null), amount (decimal 12,2),
  source (AdjustmentSource), reason (text|null)
```
